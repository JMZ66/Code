# 已知限制

本工具是证据约束的只读检查器，不是招标代理，也不是法律意见。

## 已在本环境验证

- 合成测试集 28 条金标全部命中，15 条负样本均未触发，额外发现 0。漏报率 0，误报率 0。定义见 README。
- 审查前后 SHA-256 一致；测试把样本改成只读后仍能完成审查。
- 命令行、Tkinter 界面（本机有显示）和 `self-test` 已跑通。
- 报告中的 HTML 不引用 http/https 资源。源码不导入 `requests`、`httpx`、`openai` 或 `socket`。

## 未能在本环境验证

- 不能在这台 Linux 环境里生成 Windows EXE。打包交给 GitHub Actions 的 `windows-latest`。该运行器是 Windows Server，不是 Windows 10/11 桌面，也没有在实机上用鼠标点过界面。
- EXE 未做代码签名。
- 没有用企业真实标书测量漏报率和误报率。合成集覆盖了任务要求的矛盾类型，但不能代替现场评测。
- 没有验证加密 PDF、老式 `.doc`、扫描件、带复杂修订的第三方文档，以及 Excel 公式缓存值。

## 方法上的边界

- 字段抽取是模式匹配：标签、数字和单位要出现在同一分句里。没有标签的数字不会被当成工期或金额。
- 同义词很少。除了文档里写明的别名和规则文件里的 `subject_aliases`，工具不会猜测“考核工期”就是“总工期”。
- “不低于 20”和“为 25”不冲突，因为 25 满足下限；两个不同的下限会报告，因为合格标准变了。
- 效力顺序只来自文件中的编号列表或用户规则。没有顺序时，仍然可以报告无条件表述互相冲突，但不能指定哪一份优先。
- 表格按表头文字识别名称、数量、单位、合价。合并单元格、多级表头和不规则清单可能漏抽或错位，此时应看原文位置后人工判断。
- 格式比较的是 OOXML 里写明的字体、字号、行距、页边距、分节、页眉页脚、样式编号和表头。不渲染页面，不比较视觉上的“看起来像不像”。
- 表格单元格内部的字体不与模板逐格比较，只比较表头结构；正文里与模板相同的句子会比较格式。
- 中文数字支持常见的“一百八十”“壹仟贰佰”这一类，不保证所有财务大写和带零的写法。
- 月不折算成天，工作日不折算成日历天。
- 可选的本地大模型没有接入。没有开关去调用网络。判断都是可复核的规则；确认不了就进入“需要人工判断”或“缺少依据”。
