# 测试报告

本文只写已经发生的测试。Windows 上的构建和离线冒烟以 GitHub Actions 的实际日志为准；撰写本节时那次运行还没有开始，所以这里不填写通过或失败。

## 本地自动化测试

环境：Linux，Python 3.12.3，虚拟环境里的依赖版本与 `pyproject.toml` 的直接依赖一致。这不是 Windows 10/11，也不是 Windows Server。

命令：在 `gcms_knowledgebase` 目录执行 `python -m pytest -q`。

结果：23 项通过，最近一次完整运行大约 10 秒。失败数为 0。测试名称覆盖：

- mzML 往返，以及公开文件 `small.pwiz.1.1.mzML` 的 TIC 与 pyteomics 独立求和一致（该测试约 0.37 秒）
- TIC、BPC、EIC 的已知数值
- 高斯峰面积与解析面积相差小于 3%，两个分开的峰各自积分
- van den Dool–Kratz，包括碳数不连续和外推
- 共流出合成数据解出两个组分，特征离子没有互相认错
- matchms `CosineGreedy` 的正向分数与库函数返回值一致；多出来的杂质离子会降低正向分数，反向分数回到 1
- MSP 中文名称、CAS、分子式、保留指数往返
- 导入前后原始文件 SHA-256、大小和权限不变；删除库内样品也不删原始文件
- 未配置转换器时 RAW 导入失败且文件字节不变；假转换器成功时哈希不变；假转换器改写原始文件时入库中止
- 相似度高于 0.9 不会产生确认记录；非法结论类型和过短的标准品证据被拒绝
- 按名称检索时，谱库条目和确认结论不会串层
- 3000 条合成样品及峰的插入、按样品编号的索引查询、单样品特征离子检索写在 `test_scale_search_uses_index` 里。pytest 报告的该项用时 0.05 秒。查询计划要求使用 `idx_samples_code` 或 SEARCH
- 备份恢复后旧样品回来、新样品不在；恢复前的安全 zip 里仍能看到被替换的数据；改坏一个字节的备份被拒绝，当前库不变
- Excel 工作表含“谱库候选”和“确认结论”，没有“鉴定结果”；PDF 能抽出“谱库候选（未确认）”和确认化合物名，文件内有文泉驿字体名
- 离屏界面能导入合成 mzML、做峰检测，峰表有面积且表头不含“鉴定”
- 自检入口在子进程里导入公开 mzML，日志含 `SELF_TEST_OK`，并带上 FTMS 滤镜字符串
- 业务源码不含 `import requests`、`urllib.request`、`http.client`、`pubchempy`、`socket.create_connection`。连通性探测只在 `net_probe.py`，且只由 `--net-probe` 调用

这些合成记录在库里注明“合成”，不作为真实样品。

## Windows 与离线

GitHub Actions 工作流：`.github/workflows/gcms-knowledgebase.yml`，运行器是 `windows-latest`。

它会安装依赖、跑同一套 pytest、用 PyInstaller 打出目录版 `GCMS_KnowledgeBase.exe`，再执行 `packaging/smoke.ps1`：

1. 先运行 `GCMS_KnowledgeBase.exe --net-probe`。连上 `1.1.1.1:443` 时退出码是 2，连不上是 0。
2. 用 Windows 防火墙给这个 exe 加一条出站阻止规则。
3. 再探测一次。
4. 运行 `GCMS_KnowledgeBase.exe --self-test`。自检导入随包的公开 mzML，写出扫描数、TIC 总和和滤镜字符串，然后退出。
5. 删除防火墙规则。

只有“加规则之前退出码为 2、加规则之后为 0”时，日志才写 `FIREWALL_VERIFIED`。如果运行器本来就没有出站网络，日志写 `FIREWALL_INCONCLUSIVE`，不能把它说成已经证明防火墙生效。自检失败则工作流失败。

`windows-latest` 是 Windows Server，不是 Windows 10 或 Windows 11 桌面。工作流地址：

https://github.com/JMZ66/Code/actions/workflows/gcms-knowledgebase.yml

已完成的一次构建：https://github.com/JMZ66/Code/actions/runs/41820746554 （提交 `eaf3016`，结论 success）。那次的 pytest 和 PyInstaller 完成了，zip 约 225 MB，里面有 `GCMS_KnowledgeBase.exe`。同一次的 `offline-probe.txt` 是：

```text
BEFORE
FIREWALL_ADD Ok.
AFTER_BLOCK 0
SELFTEST 0
FIREWALL_INCONCLUSIVE before= after=0
```

制品里没有 `selftest.log`。窗口程序在 Windows PowerShell 里用 `&` 调用时，`$LASTEXITCODE` 没有记下进程退出码，`BEFORE` 是空的，`SELFTEST 0` 不能当成 exe 真的返回了 0。所以这次不能写成“已经启动 exe 并导入了文件”，也不能写成防火墙对比已经成立。更正退出码读取之后的运行：https://github.com/JMZ66/Code/actions/runs/41823241987 （提交 `1ebc511`）。`offline-probe.txt` 原文是：

```text
BEFORE 2 args=--net-probe
AFTER_BLOCK 0 args=--net-probe
SELFTEST 1
SELF_TEST_FAIL [Errno 2] No such file or directory: ...\_internal\psims\controlled_vocabulary\vendor\psi-ms.obo.gz
```

防火墙对比是成立的：加规则前探测退出码 2（连得上 1.1.1.1:443），加出站阻止后退出码 0。自检没有成功，因为打包后的程序去 psims 安装目录找 PSI-MS 词表，那个文件没有打进 exe。随后的提交把 `psi-ms.obo.gz` 放进程序自己的 resources。在看到新的 `SELF_TEST_OK` 之前，不能说打包后的程序已经导入了测试文件。
