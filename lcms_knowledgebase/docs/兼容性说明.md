# 兼容性说明

这里只写实际跑过的文件和模式。没有跑过的不写成已经支持。

测试环境是 Linux 上的 Python 3.12，以及 GitHub Actions 的 `windows-latest`。`windows-latest` 是 Windows Server 镜像，不是实验室的 Windows 10 或 Windows 11 桌面。桌面系统上的显示、字体和杀毒软件没有在真实 Win10/11 电脑上复测。

## 已用真实公开文件核对的内容

| 文件 | 仪器 / 来源 | 实际读到的采集 | 核对了什么 |
| --- | --- | --- | --- |
| `tests/data/public/pymzml_example_qexactive_pos.mzML` | Thermo Q Exactive，ESI，Xcalibur，ProteoWizard 3.0.3768 从 RAW 转出 | 11 张质心正离子 MS1，没有 MS/MS，保留时间只有大约 0.05 分钟 | 能读出 Q Exactive 词条、正离子、MS1、质心、分钟为单位的保留时间；TIC 等于峰强度之和。文件头 count 写 2918，与实际 11 张不符 |
| `tests/data/public/arabidopsis_waters_pos_ms1.mzML` | Waters raw / MassLynx，仪器词条只有 “Waters instrument model”，没有具体型号。CC-BY 4.0，拟南芥 LC-ESI-MS | 800 张质心正离子 MS1，保留时间约 0.07–34.6 分钟，没有 MS/MS，没有负离子 | 能识别 Waters、正离子、MS1，并能按时间顺序读完 |

这两份文件都没有负离子，也没有带碰撞能量的 MS/MS。因此不能说 Thermo 或 Waters 的 DDA、DIA、负离子已经用真实数据验证。

## 只用合成 mzML 核对的内容

`tests/synthetic_mzml.py` 生成的文件在文件头写了 `TEST ONLY SYNTHETIC NOT ACQUIRED`。导入后界面会标明测试用合成数据。它不是任何仪器的采集。用它核对了：

- 正离子和负离子
- MS1 与 MS2
- DDA 词条（MS:1003221）以及碰撞能量 20 eV 和 40 eV，活化方式 CID 与 beam-type CID
- DIA 词条（MS:1003215）
- 没有 DIA 词条、但隔离窗口宽度 ≥ 8 Da 时标成“DIA（推断）”
- 隔离窗口宽度 ≥ 50 Da 时标成“DIA/AIF（推断）”
- SIM 词条和 SRM 词条
- TIC、BPC、EIC 与已知峰强一致，且 EIC 不把负离子算进正离子

合成 mzXML 另外核对了：极性 `+`/`-`、以秒表示的保留时间换成分钟、前体 m/z 和碰撞能量。

推断规则不是厂商方法识别。文件里没有词条时，宽隔离窗口只是一个启发式标记。

## 没有验证的内容

- 没有在 Thermo、Agilent、Waters、SCIEX、Bruker 的原始文件上运行 msconvert 或 ThermoRawFileParser。开发环境没有安装这些程序，程序也依法不附带它们。
- 没有验证 Agilent `.d`、Waters `.raw`、SCIEX `.wiff`、Bruker `.d` / `.tdf` 的实际转换。
- 没有验证离子淌度维度。文件里若有漂移时间，当前界面不展示淌度轴。
- 没有做色谱峰检测、特征提取或定量曲线。空白和 QC 用的是整条 EIC 或 TIC，不是积分峰面积。
- MZmine 和 MS-DIAL 只提供“若本机已安装则启动”的按钮，没有把它们的算法接进来，也没有用它们跑过数据。
- 轮廓谱可以读出并显示，但没有做自己的峰提取。公开测试文件都是质心谱。
