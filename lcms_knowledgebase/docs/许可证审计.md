## PySide6 / Qt（LGPL）

PySide6 6.12.0 的元数据写的是 `LGPL-3.0-only OR GPL-2.0-only OR GPL-3.0-only`。本程序选择 LGPL-3.0-only 这一支，这样应用程序自身可以保持 MIT。

为此做了这些事：

- 使用官方、未修改的 PySide6 / Qt 二进制。
- 发布物是目录而不是单文件，Qt 和 Shiboken 的 DLL 单独存放，用户可以换成兼容版本。
- 本文件和 `THIRD_PARTY_LICENSES.md` 说明使用了 Qt，并指向 LGPL-3.0 的条款：https://www.gnu.org/licenses/lgpl-3.0.html
- 应用程序源码在本仓库。

没有把完整的 Qt 源码树放进发布压缩包。Qt 公司的说明认为，仅仅链到上游网页不一定满足 LGPL 对“提供对应源码”的要求。若要把本程序再分发给第三方，分发者应按所用 PySide6 的确切版本自行提供 Qt / PySide6 源码或书面提供方式。实验室内部使用时，这一条请由本单位确认。

## 评估过但不打包的组件

### pymzML

MIT。它只读 mzML，不读 mzXML，也不算分子式质量。本程序改用同时覆盖这三件事的 pyteomics，因此运行时不依赖 pymzML。测试数据里有一份来自 pymzML 仓库的示例 mzML，文件本身随测试保留，见 `tests/data/public/PROVENANCE.md`。

### ProteoWizard / msconvert

核心代码是 Apache-2.0。官方 Windows 安装包还带有 AB SCIEX、Agilent、Bruker、Shimadzu、Thermo RawFileReader、Waters 等厂商库，这些库各自限制再分发。ProteoWizard 的说明写明：再分发时必须同时遵守这些厂商协议。本程序不附带 msconvert，也不附带任何厂商 DLL。用户安装 ProteoWizard 之后，把 `msconvert.exe` 的路径填进设置。

### ThermoRawFileParser 和 RawFileReader

ThermoRawFileParser 仓库的代码许可证是 Apache-2.0。它调用的 Thermo RawFileReader / MSFileReader 不是 Apache。Thermo 的协议（仓库中的 `THERMO_LICENSE`，审计时核对过文本）主要包括：

- 可以安装使用。
- 只有和你自己的程序放在一起时才可以再分发，并且要让最终用户同意不再继续分发。
- 软件的“关于”里要有 Thermo 的版权声明。
- 未经 Thermo 书面同意，不得商业利用，包括收费、收许可费或以此交换对价。
- 不得把该库放进受 GPL 约束的合并作品。

因此本程序不附带 ThermoRawFileParser，也不附带 RawFileReader。需要时由用户单独安装，并自己承担 Thermo 协议。本程序不会在关于框里宣称自己带有该库。

### MZmine

当前 GitHub 仓库 `mzmine/mzmine` 的 README 写源码是 MIT。已归档的 MZmine 2 是 GPL-2.0。mzio 网站的计划说明（2026-11-04 查看 https://mzio.io/plans/）把学术社区版和付费商业版分开，商业使用并不自动包含在社区计划里。本程序不打包 MZmine，只在用户填了本机路径时启动它。请按你实际安装的那一版的许可使用。没有用 MZmine 跑过本程序的数据。

### MS-DIAL

`systemsomicslab/MsdialWorkbench` 写源码是 LGPL-3.0，同一篇 README 又写程序集是 CC-BY 4.0，两处不一致。Zenodo 上较早的 MS-DIAL 记录写的是 LGPL-3.0-or-later。官方发布版含有不能随源码分发的厂商读取库。本程序不打包 MS-DIAL，只提供可选的本机启动。没有把它的算法接进来。
