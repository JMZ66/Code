# 调用说明

`office-kit` 是给下游智能体用的 Word / Excel 解析、核对和最小改写库。默认不联网，不调用模型。解析结果都是源文；只有你自己接入的推断接口才会产出 `origin="inference"` 的发现，并且正文以 `【推断】` 开头。

安装（在 `office-kit/` 目录）：

```bash
python -m pip install -r requirements.txt
```

开发依赖另加 `requirements-dev.txt`（pytest、xlwt）。

## Python

```python
from office_kit import (
    parse_document,
    document_outline,
    read_section,
    read_paragraphs,
    read_table,
    read_cells,
    search_document,
    check_files,
    diff_files,
    propose_edit,
    apply_edit,
)

doc = parse_document("招标文件.docx")
print(doc["source"]["sha256"], doc["status"])

outline = document_outline("招标文件.docx", limit=20)
section = read_section("招标文件.docx", anchor=outline["items"][0]["anchor"])
rows = read_paragraphs("招标文件.docx", start=0, end=10)
table = read_table("招标文件.docx", index=0, limit=20)
cells = read_cells("清单.xlsx", "清单", "A1:D20")
hits = search_document("招标文件.docx", "扬程")

report = check_files(["招标文件.docx", "投标文件.docx", "清单.xlsx"])
for finding in report["findings"]:
    print(finding["origin"], finding["rule_id"], finding["evidence"][0]["anchor"])

plan = propose_edit(
    "招标文件.docx",
    "word/document.xml#/document/body[0]/p[0]/r[0]/t[0]",
    "新文本",
    old_text="旧文本",
)
apply_edit(
    "招标文件.docx",
    plan["anchor"],
    "新文本",
    "招标文件.edited.docx",
    old_text="旧文本",
)
```

分页参数：`limit`（默认 40，最大 200）、`max_chars`（默认 8000，最大 20000）、`offset` / `start` / `end`。返回里看 `truncated` 和 `next_offset`。不要把 `parse_document` 的整包 JSON 塞进模型上下文；用大纲、节、表、区域和搜索。

`read_paragraphs` 的 `end` 是开区间。`read_cells` 的区域写成 `A1:D20`。

### 命令行

```bash
python -m office_kit outline 招标文件.docx --limit 20
python -m office_kit search 招标文件.docx 扬程
python -m office_kit check 招标文件.docx 投标文件.docx 清单.xlsx
python -m office_kit diff 旧.docx 新.docx
python -m office_kit edit 招标文件.docx \
  --anchor 'word/document.xml#/document/body[0]/p[0]/r[0]/t[0]' \
  --old 旧文本 --text 新文本 --output 招标文件.edited.docx
python -m office_kit mcp
```

`edit` 不加 `--overwrite` 时，输出路径不能是原文件。`--dry-run` 只给出计划。

### 核对规则

`check_files` 默认跑这些确定性规则：

| rule_id | 在看什么 |
| --- | --- |
| `amount.line` | 数量 × 单价 与合价 |
| `amount.total` | 明细合价之和与合计行 |
| `amount.cross_file` | 同一名称（投标总价、合同金额等）在多个位置的金额 |
| `amount.capital` | 同一段里的阿拉伯数字与大写金额 |
| `param.compare` | 表头能对上“参数 / 招标要求 / 投标响应”时，响应是否满足 ≥、≤ 或区间 |
| `threshold.vs_scoring` | 业绩“不少于 N 个”与“每 M 个得 X 分”，M < N 时报疑似冲突 |
| `personnel.qualification` | “项目经理须具备一级建造师”一类句子与人员表 |
| `clause.consistency` | 同一级标题下、同一条款号的正文是否一致 |

可用 `profile` 关掉规则或把名称并成一组：

```python
check_files(paths, profile={
    "disabled_rules": ["clause.consistency"],
    "compare_labels": [["投标总价", "清单合计"]],
    "clause_limit": 50,
})
```

没有写明单位的邻居单元格按“元”参加比较，这时若只有它和明确单位的金额不同，类别是“疑似冲突”。两处都写了单位却不相等，是“确定错误”。

### 推断接口

默认不调用。传入的对象只要有 `infer(request) -> list[dict]`。`request["excerpts"]` 是带锚点的摘录，不是整文件。返回的每条必须自带 `evidence[{anchor, quote}]`，否则丢掉。引擎会强制 `origin="inference"`，并在消息前加上 `【推断】`。

```python
class LocalNotes:
    name = "local-notes"
    def infer(self, request):
        return []

check_files(paths, semantic=LocalNotes())
```

不要在 `infer` 里访问网络。本库也不会。

### 最小改写

锚点必须指到一个 `w:t` 或 `w:delText`，或 `xl/worksheets/sheetN.xml#cell:B12`。

- 只改这个节点。样式、节属性、其他 run 不动。
- 共享字符串单元格改成该格的 `inlineStr`，不改 `sharedStrings.xml`，避免波及别的格子。
- 公式单元格默认拒绝。`allow_formula=true` 且新文本以 `=` 开头时，只替换公式文本，缓存和计算链不更新，结果里会警告。
- 写出前比对：除目标部件外，各部件解压后的 SHA-256 必须与原包一致；目标部件的结构差异必须落在该锚点之下。
- 原文件默认不覆盖。`overwrite=true` 时才替换原路径，并在替换前先写临时文件、检查通过再换上。

改写结果里的 `verification.warnings` 会列出图表、SmartArt、域、修订、公式、计算链等“字节没变，但打开 Office 后仍可能刷新”的对象。

## MCP

stdio，消息帧是 `Content-Length`。不要加网络传输。

```json
{
  "mcpServers": {
    "office-kit": {
      "command": "python",
      "args": ["-m", "office_kit.mcp_server"]
    }
  }
}
```

若解释器找不到包，把 `env` 里的 `PYTHONPATH` 指到 `office-kit/src`，或先 `pip install -e office-kit`。

工具：

| 工具 | 作用 |
| --- | --- |
| `list_outline` | 标题大纲或工作表名，分页 |
| `read_section` | 某一节，直到下一个同级或更高级标题 |
| `read_paragraphs` | 段落序号区间 |
| `read_table` | 表格，含合并和嵌套表锚点 |
| `read_cells` | 工作表上的 A1 区域 |
| `search` | 正文、修订前文本、批注、单元格；返回锚点和片段 |
| `run_checks` | 确定性核对 |
| `diff_documents` | 部件哈希和同锚点文本差 |
| `propose_edit` | 只检查能不能改，不写盘 |
| `apply_edit` | 写到新文件并做完整性检查 |

每次返回都带 `source.sha256`、`status`、`warnings`。内容超过 `max_chars` 时 `truncated` 为 true。

`.doc` 没有 LibreOffice 时，这些工具仍返回，`status` 为 `converter_unavailable`，并说明原文件未改。PDF 返回 `reserved`。

## 旧版 .doc / .xls

- `.docx`、`.xlsx` 直接读包。
- `.xls` 用 xlrd 读缓存值、合并和隐藏。公式文本、批注、数据有效性读不到，文档级警告 `xls_limited` 会写明，不会把空单元格假装成公式。
- `.doc` 先把原文件复制到临时目录，再调用 `soffice --headless --convert-to docx`。转换器只看见副本。未安装时不要自行改扩展名硬读。
