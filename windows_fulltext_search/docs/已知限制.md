# 已知限制

- 没有数字签名。
- 界面不使用 WebView2。字体随包附带。
- 不是完整沙箱。解析子进程有超时；Windows 上使用 Job Object 限制内存并在结束时杀掉进程。没有 AppContainer，也没有承诺能挡住所有恶意文档。
- 不执行宏、脚本、公式。Excel 只使用文件里已经缓存的计算结果。没有缓存值的公式不会被算出来，也不会把公式文本当成计算结果。
- 扫描版 PDF 没有文字层时无法检索正文，程序不会把它说成 OCR。
- 中文 PDF 没有用嵌入中文字体的样本验证。已验证的是带英文文本层、能分出页码的 PDF。
- `.doc`、`.xls`、`.ppt`、`.xlsb` 的读取代码来自 office_oxide 0.1.16，但本仓库没有对应的真实二进制样本，不能写成已验证。
- 不支持 WPS 专用格式。
- 在这个 Tantivy 版本上，一次提交里写入多份文档之后，按路径做的删除有时删不掉倒排里的旧文档。搜索会对照清单里的代数：只有当前这一版才算命中，被删的路径直接排除。旧副本可能还占着索引空间，但不会再出现在结果里。段合并且保持关闭，避免合并把这种删除状态搅乱。
- 索引含正文，不加密。
- 正则如果抽不出必须出现的字面量，会在已保存的文本上逐份核对，可能慢，可以取消，界面会说明。
- 普通用户运行，不读 NTFS MFT，也不捆绑 Everything。
- GitHub 上的 Windows 构建机是 Windows Server，不是 Windows 11 桌面。没有在 Win11 上做鼠标点击测试。
