# 性能报告

数字来自 2026-11-08 在本云端虚拟机上的 release 构建。查询计时是引擎内部：倒排预筛加上对已保存原文的精确核对，不含界面和进程间通信。每种查询先跑一遍预热，再重复 8 次。下面的 P50/P95 是热缓存。

## 机器

- CPU：Intel Xeon（KVM），4 核，`nproc` = 4
- 内存：约 16 GB
- 系统：Linux
- 磁盘：`/dev/vdc`，ext4，约 254 GB。`lsblk` 把这块盘标成旋转盘（ROTA=1）。这是虚拟磁盘，不是一块已经确认的台式机 SSD
- 构建：`cargo build --release`，thin LTO，codegen-units = 8
- 索引写入：单线程，关闭段合并，10 万份文件一次提交

## 10 万份合成文本

文件是程序生成的 UTF-8 文本，不是 10 万份 Office 文档。每份几行，其中一部分包含“包装材料质量检测报告”，并带有 `sampleterm`、`alpha`、`gamma` 这类词。语料是合成的。

跑了两次，结果接近：

| 项目 | 第一次 | 第二次 |
| --- | --- | --- |
| 文件数 | 100000 | 100000 |
| 建索引 | 3302 ms | 3186 ms |
| 索引大小 | 62,036,660 字节 | 62,030,565 字节 |
| 查询样本 | 40 | 40 |
| P50 | 128 ms | 132 ms |
| P95 | 686 ms | 690 ms |
| 进程峰值 RSS | 未在第一次采样 | 241,488 KB（约 236 MB） |

查询是：`sampleterm`、`质量检测`、`alpha`、`报告`、`gamma`。这些词比较挑，不是单个常见汉字扫全库。

200 ms / 800 ms 是给 SSD 上普通关键词定的目标。这次测到的 P50/P95 低于这两个数，但磁盘不是已确认的 SSD，所以不能写成“已在 SSD 上达标”。这里只记录这台虚拟机上的实测。

## 混合格式

release 版 `--self-test` 生成 22 个真实容器（docx、docm、xlsx、xlsm、pptx、pdf、odt、ods、odp、rtf、html、csv、json、xml、txt 等），完成索引、搜索、改文件、删除、改名和重启，用时 52 ms。这只说明这一小套混合文件很快，不能外推成 10 万份 Office 文档。

没有做 10 万份 Word/Excel/PDF 的全链路计时。
